# Contributing

## Workflow

1. Open an issue or discuss the change before starting large work.
2. Keep patches focused on a single area of responsibility.
3. Run the relevant pytest checks before opening a PR.
4. Document user-facing behavior and configuration changes.

## Coding standards

- Prefer explicit fail-closed validation.
- Keep protocol and security logic deterministic and testable.
- Avoid leaking sensitive data into logs.

## Pull requests

- Include a clear summary of the change.
- Attach any release or acceptance documentation affected by the patch.
- Confirm the full suite still passes before requesting review.
